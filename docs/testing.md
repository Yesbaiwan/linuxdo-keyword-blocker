# 验证与测试

改完代码怎么验证、回归怎么跑、结果怎么判读。入口是 `tests/run.js`。

## 环境

- Windows 11 + PowerShell，Node.js；测试用 `playwright-core` 驱动本机 Chrome。
- **测试专用 Chrome profile**：默认 `tests/.chrome-profile`（已 gitignore），可用环境变量 `LKCB_CHROME_PROFILE` 换。登录态每次从项目根目录的 `linux.do_cookies.txt` 导入（该文件**经常需要更换**）。
- **为什么不用日常 profile**：Chrome 136+ 只认非默认数据目录的调试端口，用日常 profile 起调试端口会弹窗要你点允许、也不被官方支持；而且日常 profile 里的油猴 / 广告拦截扩展会污染测量。
- `chrome-devtools-mcp` 只用于看页面 / 调试，不跑测试。

## 改完怎么验证

- **本站实测**：改动后在 linux.do 看三类页面各一次——最新、未读、搜索。不用推断代替。
- **别对站点做快速连续刷新 / 导航**：会触发限流，严重时封号。回归不要连着跑，两次之间留间隔；调试优先 `node tests/run.js console`（自建 mock DOM，只导航一次）。

## 套件

| 套件      | 覆盖什么                                                                                                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `console` | 功能回归主力。自建 mock DOM，不依赖站点内容：登录门槛、面板开关、规则 CRUD、类别下拉（等级顺序 / 展开不撑高面板 / 拉不到时的提示与重试 / ↑↓ 键盘导航）、标签框增删与「零标签」收起、匹配语义（类别精确 / 所有等级 / 标签精确 / 多标签 AND / 零标签 / 标题包含 / 大小写不敏感 / 组合 AND / 搜索页嵌套行）、启停、行内编辑、导入、存储损坏回退 |
| `spa`     | 真实信息流 + SPA 页内路由。点站点导航标签切换列表（页面不重载、脚本实例存活），验证切换后过滤照常、无残留状态、零报错。规则用两条「仅标题」：探测词（取首页第一条标题）+ 高频字「的」，保证重建出的新列表必有命中行 |
| `perf`    | 性能与抖动。加载 `fixtures/rules-sample.json`（27 条真实规则集）并滚动加载多页；**淡化 / 隐藏两种模式各跑一遍**（`perf-dim` / `perf-hide`），模式由 run.js 经 `window.__LKCB_PERF_MODE__` 传入 |

断言条数不写进文档：断言会随回归增长，写死必然漂移（历史上就从 69 漂到过 72）。要看条数直接看跑完的摘要行。

## 跑

```powershell
node tests/run.js          # 四跑（默认，等同 both）
node tests/run.js both     # console + spa + perf-dim + perf-hide
node tests/run.js console  # 只跑功能
node tests/run.js spa      # 只跑 SPA 路由
node tests/run.js perf     # 只跑性能两模式
```

不需要交互。流程是：

1. **查 cookie 文件**：缺失 / 没有 linux.do 条目 / 带过期时间的条目全过期 → 直接报错，不起浏览器。
2. **起专用 Chrome，导入登录态**（来自 `linux.do_cookies.txt`）。已开的调试 Chrome 会复用启动时那个空白标签页，不另开。
3. **前置检查**：导航 `/latest` 一次（同时完成预热），判定站点可达 + 登录态。
4. 通过才逐套跑完并关掉页面。

第 3 步里，**cookie 失效**（没登录上，或被 Cloudflare 挑战页拦住）、站点打不开、列表没出来，都直接停下并说明原因，**一套都不跑**（退出码 1）。cookie 失效时要重新导出一份 `linux.do_cookies.txt` 覆盖，再重跑。

## 输出

终端只打摘要（全绿是 `✅ 套件：n/n 通过`），失败会把失败项与实际值一并列出；完整断言明细落盘 `tests/.last-result.json`（已 gitignore），只在需要复盘时才读。

## 判读

- 只看退出码和摘要行；失败项自带实际值，明细在 `.last-result.json`。
- **偶发失败先怀疑环境**（网络、页面没就绪、机器负载），重试再判断，**不要给环境打补丁**。
- **`perf` 的判定项**：① 首屏同一行状态只写一次（不反复跳）；② 稳定后已存在的行不再被重写状态；③ observer 单次回调 ≤ 250ms、累计 ≤ 2000ms（patch `MutationObserver` 计 `handleAddedNodes`）；④ 全程无脚本自身的 JS 报错；⑤ 全过程每行状态只写一次、滚动加载期间 CLS ≤ 0.01。
- **`perf` 只报告不判定**：「内容到达 → 状态落地」的延迟分位数、CLS 首屏。前者同一份代码实测 p95 在 15～230ms 之间跳，主要被站点自身的渲染 / hydration 长任务占着；后者在隐藏模式下必然偏高（把命中行从布局里摘掉、下方内容上移），是模式固有代价。卡阈值只会随机红。
- **`spa` 的 CLS 增量**只报告 + 宽松兜底（≤ 0.05），站点自身重排也会产生位移。
- **只断言「行为与过滤语义」与「脚本自身开销」**：不测 CSS 像素。
- **「零 JS 错误」只算脚本自己的错**：`Script error.` 是跨域脚本（站点 CDN / Turnstile）的不透明报错，直接忽略——注入的脚本不是跨域，真报错必然带真实 message；perf 另外包住 `handleAddedNodes` 捕获回调抛错。
- **站点结构变了 / 页面没内容时跳过而不是判失败**，避免假红。
- 写死的值只有分类「开发调优 = 4」「搞七捻三 = 11」；分类名与子分类 ID 都从类别树动态取，避免硬编码。
- 不做（用户明确无需或需人工）：导出下载、导入的系统文件选择框、真实登出、真实油猴环境冒烟。

## 两条硬约束

- **CSP**：脚本每份文档只允许 eval 一次，且必须在 evaluate 的同步栈内；`await` 之后的定时器里 eval 会被站点 CSP 拦。所以套件源码用同步 XHR 从 [serve.js](../tests/serve.js)（由 run.js 内嵌启动，127.0.0.1:8123）拉，保持同步栈。由此还有两个连带后果：**注入前必须把设置与取证设施都准备好**（都在首个 `await` 之前）；console 里「存储形状损坏」的回退路径无法二次注入验证，改由「导入合法 JSON 但不是规则数组」的用例钉住（共用同一守卫）。
- **预热**：perf 的量在**热页面**上（run.js 先空跑一轮）。冷缓存那次会被站点自身的加载 + hydration 拖着走，测的不是脚本。console 也会强制走真实拉取、避开上一轮留下的 7 天缓存。

## 双实例检查

**注入前先查页面里有没有别的脚本实例**（`__lkcbLoaded` / `#lkcb-panel` / `#lkcb-overlay` 任一存在即为双实例，结果不可信）。命中就**直接停下、不做任何断言**、退出码 1，让你先处理；专用 profile 是自建的，不会有你装的扩展。

## 隐私红线

- [tests/serve.js](../tests/serve.js) 只放行白名单（`ld-blocker.user.js` + `tests/suites/` + `tests/fixtures/`），其余 403——它带 CORS `*`，而项目根下就是 `linux.do_cookies.txt`。
- 每轮跑前会 `clearResult()` 清掉上一轮结果，避免读到旧数据。
- **cookie 文件永远不进 git。**
